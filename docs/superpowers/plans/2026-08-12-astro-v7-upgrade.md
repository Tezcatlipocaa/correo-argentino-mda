# Astro v7 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Portal MDA from Astro 6 to Astro 7 while preserving SSR behavior, Node standalone deployment, UI whitespace, Astro Actions, React islands, and existing regression coverage.

**Architecture:** Use Astro's official npm upgrader to update Astro and official integrations together, then make only repository-specific compatibility changes. Keep advanced routing disabled because this app already uses `src/middleware.ts` and has no custom `src/fetch.ts` entrypoint. Preserve Astro 6 HTML whitespace behavior explicitly with `compressHTML: true`, then validate Rust compiler output, Vite 8 integration compatibility, SSR build output, PM2 entrypoint, and Playwright flows.

**Tech Stack:** Astro 7, Vite 8, `@astrojs/node` standalone, `@astrojs/react`, `astro-icon`, Tailwind CSS v4 with `@tailwindcss/vite`, React 19, TypeScript 5.9, Node 22+, Playwright.

## Current Repository Findings

- `package.json` declares `astro: ^6.2.2`, `@astrojs/node: ^10.1.1`, and `@astrojs/react: ^5.0.4`.
- Installed versions are Astro `6.4.7`, `@astrojs/node` `10.1.4`, and `@astrojs/react` `5.0.7`.
- `astro.config.mjs` uses SSR output, Node standalone mode, React, `astro-icon`, Tailwind's Vite plugin, and a Rollup external for `ldapjs`.
- Node runtime is `v24.16.0`; `package.json` already requires `>=22.12.0`, satisfying Astro 6+ requirements.
- No `src/fetch.ts` or `src/fetch.js` exists; no `fetchFile` config is required.
- No Markdown or MDX files exist; Astro v7's Sätteri Markdown default does not affect this repository.
- No `@astrojs/db` dependency exists; database code uses Drizzle plus `better-sqlite3` directly.
- No deprecated `astro:transitions` internals or `getContainerRenderer()` imports exist.
- Existing worktree contains unrelated user changes. Do not reset or include them in upgrade commits.
